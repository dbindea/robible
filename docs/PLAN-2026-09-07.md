# RoBible — Reenfoque de producto: UX móvil, perfiles y módulo de predicación

## Contexto

RoBible está en producción con usuarios reales. El roadmap actual arrastra una lista de
pendientes heredada (nickname hints, paths por idioma, avisos de lint, expansión SEO de
`/versiculos/*`…) que ya no refleja hacia dónde quiere ir el producto.

Este plan **sustituye** esos pendientes. El objetivo es doble:

1. **Limpiar el UX existente en móvil**: el selector de idioma no dice qué idioma está
   activo, la búsqueda muestra el historial cuando no debe, el cambio entre modos de
   búsqueda pierde el texto escrito, y cada versículo arrastra siete iconos permanentes.
2. **Abrir el producto a los predicadores**: un tipo de usuario nuevo con un módulo
   completo de preparación de predicaciones que culmina en un Modo Amvon que debe
   funcionar sin conexión.

Principio rector: **evolucionar lo que ya existe, no duplicarlo**. Casi todo lo que se
pide tiene una implementación parcial en el repo; el trabajo es mayormente corregir y
extender, no construir de cero. La única pieza realmente nueva es el módulo de predicación.

### Decisiones tomadas contigo

- **Respuesta de seguridad**: texto libre 1-100 caracteres, normalizada al comparar
  (minúsculas, sin diacríticos, espacios colapsados). Los usuarios actuales con respuesta
  numérica siguen funcionando: su hash no cambia.
- **Email**: se guarda la columna y el campo en la interfaz; el envío de correo queda
  documentado como pendiente. Sin dependencias nuevas ahora.
- **Música**: los tres ambientes procedurales, extendiendo `music.service.js`.

## Restricciones que respeta el plan

- Svelte 5 en sintaxis legacy (`export let`, `$:`), sin runes.
- Comentarios en castellano explicando el *porqué*.
- Ningún texto en duro: toda clave nueva en los **cuatro** `public/lang/*.json`
  (`tests/i18n-keys.test.js` lo verifica).
- Servicios nuevos con el patrón API-first + fallback a localStorage (`withFallback`).
- SCSS con tokens de `public/global.css`; nunca colores literales.
- Sin librerías nuevas.
- El evento de navegación se escribe con la errata: `robibile:navigate`.
- Tocar `public/sw.js` obliga a bumpear `CACHE_NAME`.
- `npm run lint` debe salir en 0 errores.

### 4.A Aspecto del player

**Fichero**: [TtsPlayer.svelte](src/components/TtsPlayer.svelte), regla `.tts-bar`.

### 4.B Tres ambientes procedurales

**Fichero**: [music.service.js](src/services/music.service.js).

Extender `CHORD_INTERVALS` y la selección de pista a tres ambientes con identidad propia:

1. **Ebraică** — escala frigia dominante (el modo *Ahava Raba* de la liturgia judía):
   segunda menor y tercera mayor sobre la tónica. Es exactamente esa sonoridad, generada,
   sin copiar ninguna grabación.
2. **Rugăciune** — drone grave y envolvente: fundamental una o dos octavas por debajo de

que es lo más parecido a lo que venía escuchando.

Decidir qué hacer con `prayer-ambient.mp3`: si ningún ambiente lo usa, retirarlo del repo
junto con su entrada en CREDITS.md (son 2,3 MB) o conservarlo documentado como alternativa.

## FASE 5 — Módulo «Predicile mele»

Sólo visible para `userType === 'preacher'`.

**Principio innegociable**: RoBible **no escribe la predicación**. Guía, estructura y
presenta lo que escribe el predicador. Sin IA, ni como dependencia ni como opción.

### Persistencia

**Schema (versión 9)** — dos tablas, no seis:

```sql
CREATE TABLE sermons (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  title TEXT,
  book INTEGER, chapter INTEGER, verse_start INTEGER, verse_end INTEGER,
  version TEXT,                      -- versión bíblica con la que se preparó
  type TEXT NOT NULL DEFAULT 'expositive',
  status TEXT NOT NULL DEFAULT 'draft',   -- draft | ready | preached
  series TEXT,
  content_json TEXT,                 -- todo el proceso de preparación
  outline_json TEXT,                 -- la schiță, artefacto independiente
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL, prepared_at TEXT,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
```

El proceso de preparación (observaciones, contexto, idea, estructura, desarrollo) es un
árbol profundo y variable. Modelarlo en tablas relacionales daría seis tablas y un JOIN
por pantalla, sin ganar nada: **nunca se consulta por dentro**, siempre se carga entero.
Va en `content_json`. Las columnas escalares existen sólo para listar y filtrar.

`outline_json` va aparte porque la schiță es un artefacto distinto y editable por separado:
la predicación tiene 1.500-2.500 palabras y la schiță 150-250.

**Servicio y store**: `sermons.service.js` + `sermonsStore.js` siguiendo
[favorites.service.js](src/services/favorites.service.js) — API-first con fallback a
localStorage. Aquí el fallback no es un extra: es lo que sostiene el requisito offline.

**Guardado automático**: escritura inmediata a localStorage y `PATCH` con debounce
(~2 s) al backend. Indicador discreto «Salvat», sin botón de guardar.

### Rutas

Ruta nueva `/predici` (trampa 11: tocar `Main.svelte`, `bible-versions.js`,
`AppMenu.svelte`; **no** `generate-seo.mjs`, porque es privada y va con `noindex`).

Pantallas, todas mobile-first:

- **K1 Lista** — tarjetas con título, texto bíblico, tipo, estado y fecha. Filtros
  Toate/În lucru/Pregătite/Predicate. Búsqueda por título o texto. Acciones según estado.
- **K2 Predică nouă** — selección de libro/capítulo/versículo inicial y final reutilizando
  [BookDrawer.svelte](src/layouts/main/BookDrawer.svelte) y `buildBiblePath`. Muestra la
  perícopa completa. Tipo (expozitivă por defecto). Título opcional.
- **K3 Pregătire** — proceso guiado por pasos, no un formulario gigante:
  TEXT → OBSERVARE → CONTEXT → IDEE → STRUCTURĂ → DEZVOLTARE → FINALIZARE.
  Se puede retroceder y saltar preguntas. Nada obligatorio.
  - *Text*: marcar palabras y añadir notas, asociadas a esta predicación (**no** a los
    subrayados globales del usuario: son cosas distintas y mezclarlas ensuciaría la Biblia).
  - *Context*: perícopas anterior y posterior, abiertas sin salir de la preparación.
  - *Structură*: puntos y subpuntos, **máximo dos niveles**, reordenables, con referencias.
  - *Dezvoltare*: por punto, Explică / Ilustrează / Aplică, con referencias marcables como
    «sólo mencionada» o «leída en el púlpito».
- **K4 Predica finală** — documento limpio, con recuento de palabras y minutos estimados
  (orientativo). Acciones: editar, crear schiță, marcar como preparada.
- **K5 Schița** — generada desde la estructura ya escrita, sin IA, y **completamente
  editable**. Títulos, palabras clave, contrastes, referencias. Nunca un resumen largo.

### K6-K9 Modo Amvon — la parte crítica

- **«Pregătită pentru predicare»** guarda en local, sin descarga manual: predicación,
  schiță, perícopa y **el texto de todas las referencias citadas**. Mensaje simple de
  confirmación.
- **Interfaz**: se oculta menú, cabecera, navegación y toda acción secundaria. Queda la
  schiță. Tipografía muy grande, alto contraste, espaciado generoso.
- **Navegación**: página vertical continua con separadores claros entre puntos.
  **No** modelo de diapositivas: nada de Next/Previous.
- **Tamaño de letra** elegido antes de empezar (A− A A+), recordado; los controles no
  permanecen visibles durante la predicación.
- **Pantalla activa**: `navigator.wakeLock`. Si no está disponible, no bloquear el modo
  ni repetir errores.
- **Cronómetro** opcional y discreto (`18 / 35`). Sin alarmas ni animaciones.
- **Referencias**: tocar una abre un overlay con el texto y al cerrarlo se vuelve
  **exactamente** a la misma posición del scroll.
- **Offline de verdad**: durante el modo Amvon no se hace **ninguna** petición de red y
  no puede aparecer ningún mensaje de conexión. Todo sale de localStorage y de la Biblia
  que el SW ya tiene cacheada.
- **Recuperación**: la posición del scroll se guarda en local cada pocos segundos; al
  volver de una llamada o de bloquear el teléfono, se reabre la misma predicación en modo
  Amvon y en la posición aproximada.

## FASE 6 — Verificación

Los seis escenarios de la especificación, probados en móvil real (390×844) y escritorio,
en tema claro y oscuro:

1. **Búsqueda** — foco con input vacío → 3 elementos de historial con scroll. Escribir
   `prov 3 4` → historial desaparece. Cambiar a Referință sin borrar → el texto se
   mantiene, el estado anterior se resetea y aparece la sugerencia *Proverbe 3:4*.
2. **Versículo** — en estado normal sólo Copy. Tocar un versículo lo selecciona y aparecen
   las acciones. Tocar otro mueve la selección.
3. **Color** — subrayar en amarillo: el icono usa amarillo y **no queda azul por ningún
   lado**. Comprobar explícitamente en **modo oscuro**, que es donde está el fallo.
4. **Predicator** — crear usuario Predicator → aparece «Predicile mele». Crear usuario
   Utilizator → no aparece.
5. **Predicación offline** — crear, finalizar, crear schiță, marcar preparada, entrar en
   Modo Amvon y **cortar la conexión**: todo sigue, las referencias se abren, el scroll
   funciona y no aparece ningún error de red.
6. **Interrupción** — en Modo Amvon, bajar hasta el punto 2, salir de la aplicación y
   volver: misma predicación, mismo modo, posición aproximada.

**En cada fase**: `npm run lint` en 0 errores, `npm test` en verde (con tests nuevos para
las abreviaturas de libro y para el servicio de predicaciones), `npm run build` correcto.

**Backend**: migraciones con `wrangler d1 execute --command` (la opción `--file` está rota
en wrangler 3.114) y censo de filas antes y después para confirmar que no se pierde nada.
